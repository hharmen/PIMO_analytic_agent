# PIMO - агент-аналитик

Текст требований -> LLM строит формальную модель (конечный автомат) -> Model Checker (TLA+/TLC)
проверяет её -> LLM объясняет результат на языке требований.

Сервисы:
- `core` (порт 8000) - Core API: регистрация, чаты, агент. Swagger: http://localhost:8000/docs
- `checker` (порт 8001) - Model Checker: validator, compiler, TLC, parser
- `db` - PostgreSQL
- LLM - LiteLLM МАИ (`https://api-ai.mai.ru/v1`), модель `qwen3.8-27b`

## Запуск через Docker

```bash
cp .env.example .env        # вписать LLM_API_KEY
docker compose up --build
```

Фронтенд: http://localhost:5173. Compose собирает интерфейс и запускает nginx,
который передаёт запросы `/api/*` в Core внутри Docker-сети. Локальный Node.js не нужен.

Нужен файл сертификата `core/certs/api-ai.mai.ru.pem` (лежит в репозитории, как обновить - ниже).

Проверить агента из консоли внутри контейнера:

```bash
docker compose exec core python -m app.agent.cli "Заявку можно отменить до исполнения. ..."
```

## Срок действия сессии

Для подписи токенов задайте в `.env` случайный `JWT_SECRET`, не оставляйте `change-me`.
Сгенерировать значение: `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'`.
В production приложение требует секрет не короче 32 байт. Смена секрета делает все
ранее выданные токены недействительными; пользователи входят заново, данные в БД сохраняются.

Токен доступа действует **60 минут с момента входа**, независимо от активности.
Значение задаётся в `.env` через `JWT_EXPIRE_MINUTES=60` (положительное число минут).
После изменения пересоздайте Core: `docker compose up -d --force-recreate core`.
Новый срок применяется к токенам, выпущенным после изменения; ранее выданные сохраняют свой `exp`.

При истечении срока интерфейс показывает вход, очищает токен и скрывает переписку.
Он также проверяет пользователя через `/auth/me` при возвращении во вкладку.
Сервер отклоняет просроченные, повреждённые, неправильно подписанные токены,
токены без обязательных `sub`/`iat`/`exp` и токены удалённых пользователей с HTTP 401.
Ответ содержит `detail.code` (`token_expired`, `invalid_token` или `authentication_required`)
и понятное сообщение в `detail.message`. Ошибка email/пароля при входе остаётся отдельной ошибкой.

Черновик текущего сообщения и id чата временно сохраняются в `sessionStorage` вкладки.
После повторного входа в **тот же аккаунт** интерфейс загружает историю с сервера
и восстанавливает черновик; другой аккаунт его не получает. При явном выходе черновик удаляется.
Запросы старой сессии отменяются в браузере, их поздние ответы не меняют новую сессию.
Отмена в браузере не гарантирует остановку уже начатого анализа на сервере: после входа
проверьте восстановленную историю. Сообщение автоматически повторно не отправляется.

Автоматического продления и refresh-токенов пока нет: после часа нужен повторный вход.
Выход очищает токен в браузере; его отдельная серверная блокировка до `exp` не реализована.

## Запуск без Docker

Нужны Python 3.11+ и Java 11+. Без `DATABASE_URL` Core использует SQLite.

```bash
# терминал 1: checker
cd checker && pip install -r requirements.txt
python -m uvicorn app.api:app --port 8001

# терминал 2: core
cd core && pip install -r requirements.txt
set -a; source ../.env; set +a
python -m uvicorn app.main:app --port 8000
```

## Админ-панель

Запустите приложение: `docker compose up -d --build`.
Зарегистрируйте обычный аккаунт на http://localhost:5173, затем назначьте ему роль
из терминала сервера (подставьте email зарегистрированного пользователя):

```bash
docker compose exec core python -m app.admin.cli grant admin@example.com
```

Обновите страницу и откройте кнопку «Админ-панель» рядом с вашим email,
либо перейдите на http://localhost:5173/#/admin. Пароль остаётся тем же.
Первый зарегистрированный пользователь автоматически администратором не становится.

В панели доступны:

- количество пользователей, активных и заблокированных аккаунтов, чатов, сообщений и проверок;
- список пользователей с поиском по email, фильтром статуса и страницами по 25 записей;
- даты регистрации и последнего сообщения, количество чатов/сообщений/проверок пользователя;
- блокировка и разблокировка с подтверждением; история чатов при этом сохраняется;
- распределение результатов проверок и журнал изменений доступа, включая серверные команды.

Пока аккаунт заблокирован, он не может войти или выполнять запросы с ранее выданным JWT.
Уже запущенный анализ может завершиться на сервере. После разблокировки доступ снова разрешён.
Администраторов через панель блокировать нельзя. Пароли, хеши паролей, тексты чужих чатов
и содержимое моделей в админ-панель не передаются. Административные запросы проверяют
роль в БД на каждом обращении; обычный пользователь получает 403 даже по прямому URL API.

Снять роль с аккаунта:

```bash
docker compose exec core python -m app.admin.cli revoke admin@example.com
```

Последнего действующего администратора снять нельзя. Заблокированный аккаунт сначала
нужно разблокировать, затем назначать администратором. Неизвестный email команда не создаёт.
Для запуска без Docker выполните эту же команду из каталога `core` с настройками БД из `.env`:
`python -m app.admin.cli grant admin@example.com`.

Обновление схемы выполняется автоматически при старте Core: в `users` добавляются флаги
`is_admin=false`, `is_active=true`, создаётся журнал `admin_audit`. Поддерживаются PostgreSQL
и SQLite; пользователи, пароли, чаты и результаты сохраняются. Доступ к панели по умолчанию
закрыт всем, пока роль явно не назначена командой. API панели описан в `/docs`, раздел `admin`.

После запуска Core и checker:

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173, зарегистрируйтесь и отправьте требования агенту.

импорта документов описаны в [frontend/README.md](frontend/README.md).

## Сертификат api-ai.mai.ru

Сертификат сервера МАИ выдан Russian Trusted CA, которого нет в списке Python, поэтому без
настройки будет `CERTIFICATE_VERIFY_FAILED`. В систему ничего ставить не нужно: клиент LLM
доверяет только файлу из `LLM_CA_FILE`, в котором лежит сертификат самого сервера.

Когда МАИ обновит сертификат, снять его заново:

```bash
cd core
openssl s_client -connect api-ai.mai.ru:443 -servername api-ai.mai.ru </dev/null 2>/dev/null \
  | openssl x509 -out certs/api-ai.mai.ru.pem
openssl x509 -in certs/api-ai.mai.ru.pem -noout -subject -fingerprint -sha256 -enddate
```

## Агент (`core/app/agent/`)

- `service.py` - `run_agent(history)`. LLM вызывает инструмент `check_behavior` (tool calling),
  агент отправляет модель в checker. При `MODEL_INVALID` LLM исправляет модель (до 3 раз).
  После вердикта инструмент отключается (`tool_choice="none"`), LLM только объясняет результат
  и модель сама не меняет.
- `prompts.py` - системный промпт и описание инструмента.
- `cli.py` - запуск из консоли.

Токены: в LLM уходят последние 10 сообщений чата (старые обрезаются), результат checker'а
сжимается, расход пишется в лог и в `AgentReply.usage`.

Если модель не поддерживает tool calling: `LLM_USE_TOOLS=false`, тогда она присылает JSON текстом.

## Тесты

```bash
cd core && python -m pytest -q
```

LLM в тестах подменяется, ключ не нужен. Если запущен checker на `localhost:8001`, дополнительно
проходят acceptance-тесты из ТЗ через TLC (модели в `checker/examples/`).
